CodeQuest

A gamified learning platform for a campus coding community — built solo, from database schema to production deploy.

RoleSolo developer
Year2026
StackNext.js · Prisma · Supabase · NextAuth · Tailwind
StatusIn production

01Context

UKM Coding at Cyber University runs learning programs for members at wildly different levels — some have never written a line, some already ship side projects. Material lived in scattered documents, submissions came in over chat, and progress existed only in whoever happened to remember it.

The community needed one place where a member could see what to learn next, submit work, and have that work actually recorded.

02The problem

The obvious version of this product is a course website. That would have failed for the same reason the documents failed: nothing made anyone come back.

The real problem wasn't storage. It was retention and visibility — members dropping off after week two, and mentors having no way to see who was stuck without asking everyone individually.

03Approach

  • Modelled progress before designing screens. Courses, modules, submissions, and attempts became first-class tables in Prisma. Every interface after that was just a view over a schema that already made sense — which is why adding features later didn't require migrations.
  • Role-based access from day one. Member, mentor, and admin were built into the auth layer through NextAuth rather than bolted on. Retrofitting permissions is the single most expensive mistake in a platform like this.
  • Made progress visible, not just stored. Completion state surfaces on every entry point, so a returning member never has to remember where they left off. This is the part that changed behaviour.
  • Server components by default. Course and module pages render on the server so first load stays fast on campus wifi. Client interactivity is scoped to the pieces that genuinely need it.

04Interface

05Outcome

CodeQuest is in production and is now the default place the community runs its programs. Material, submissions, and progress live in one system instead of three, and mentors can see where people are stuck without chasing them.

The part I'd defend hardest: the schema hasn't needed a rewrite. Every feature added after launch fit the model that was there on day one.
